                               Peer Code Review Standard

Introduction
Peer code reviews are an essential part of implementing code. GitHub can require that all
changes are peer reviewed by different users.
Purpose
This document sets forth the standards for peer code reviews in GitHub.

Standard
Peer Code reviews in GitHub are a way to maintain code styles and ensure code is operational
and reviewed before deployment.
The following are standards that should be maintained when reviewing code:
   •   Objectives.
          o Improving code quality.
          o Enhancing code maintainability.
          o Increasing code reliability.
          o Promoting knowledge sharing.
   •   Project scope.
          o Code compliance.
          o Security.
          o Functionality.
          o Architecture and design.
          o Documentation and testing.
   •   High-level requirements.
          o Version control.
          o Collaboration.
          o Security.
          o Integration.
          o Documentation.
          o Customization.
          o Automation.
          o Accessibility.
          o Analytics.
          o Training and support.
   •   Any new process must meet high-level requirements if there is a change in technology.
For workflow, the following should also be observed:
   •   Stakeholders should be listed and documented.
   •   Conducting timely reviews.
   •   Understanding the changes made.
   •   Focusing on the objectives.
   •   Providing constructive feedback.
   •   Being respectful.
   •   Using the commenting feature built into GitHub.

   •   Using templates or checklists.
   •   Acknowledging contributions.
