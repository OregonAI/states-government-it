1.0.    Document Purpose
          The purpose of this document is to define the State of Maine policy and procedures
          that are in place for defense-in-depth cybersecurity of State of Maine information
          assets (see Definitions). The State of Maine defense-in-depth focuses on
          requirements related to application partitioning, information in shared resources,
          denial-of-service protection, name/address resolution, session authenticity,
          information at rest, information system partitioning, and process isolation. This
          part of the security program is focused on protecting the confidentiality (see
          Definitions), integrity (see Definitions), and availability (see Definitions) of State
          information assets. This document corresponds to the System and
          Communications Protection Procedures for Defense-in-Depth (SC-2, 4, 5, 20, 21,
          22, 23, 28, and 39) Control Family of National Institute of Standards and
          Technology (NIST) Special Publication 800-53 (Rev. 5).1
2.0.    Scope
        2.1.     These procedures apply to State of Maine employees and contractors
                 (collectively referred to as personnel in this document) with access to:
                 2.1.1. Executive Branch Agency information assets, irrespective of location;
                        and
                 2.1.2. Information assets from other State government branches that use
                        Executive Branch-managed services.
3.0.    Procedure Conflict
          If these procedures conflict with any law or union contract in effect, the terms of
          the existing law or contract prevail.

                 8.3.1. Information Asset Owners ensure that information systems prevent
                        unauthorized and unintended transfer of information through shared
                        system resources by enforcing residual information protection
                        mechanisms. These mechanisms ensure that information produced by
                        prior users, roles, or processes is not accessible to subsequent users,
                        roles, or processes after shared resources are released or reassigned.
                        8.3.1.1.    Shared system resources, including memory, storage,
                                    temporary files, buffers, and caches, are cleared,
                                    reinitialized, or otherwise sanitized prior to reuse.
                        8.3.1.2.    Operating system, platform, or virtualization controls are
                                    configured to prevent residual data exposure between users,
                                    processes, or workloads when shared resources are
                                    reassigned.

        8.4.     Denial-of-Service Protection (SC-5)
                 8.4.1. The Office of Information Technology (OIT) implements technical and
                        operational controls to protect against and limit the effects of denial-
                        of-service (DoS) events that could impact the availability of State of
                        Maine systems and services.
                 8.4.2. Denial-of-service protections address multiple event types, including
                        volumetric attacks, protocol-based attacks, and application-layer
                        attacks, through a combination of boundary protections, capacity
                        management, redundancy, and monitoring.
                 8.4.3. Boundary protection mechanisms, including firewalls and web
                        application protection services, are used to filter malicious traffic and
                        prevent denial-of-service conditions from directly impacting internal
                        systems. OIT Network Security prevents Denial-of-Service (DoS)
                        attacks (see Definitions) against web assets using a Web Application
                        Firewall (WAF) as a cloud reverse-proxy to conceal the Internet
                        Protocol (IP) addresses of web servers. The WAF:
                        8.4.3.1.   Filters malicious traffic before it reaches the web servers;
                        8.4.3.2.   Leverages a global Content Delivery Network (see
                                   Definitions) for geographic redundancy; and
                        8.4.3.3.   Provides distributed denial-of-service (DDoS) mitigation
                                   capabilities through upstream traffic filtering, scrubbing
                                   services, and scalable network protections.
                 8.4.4. Network capacity, bandwidth management, geographic distribution,
                        and service redundancy are employed to reduce susceptibility to DoS
                        events and to limit service degradation during attack conditions.
                 8.4.5. OIT employs network monitoring, telemetry, and analytics capabilities
                        to detect anomalous traffic patterns indicative of denial-of-service
                        activity and to support timely response and escalation.
                 8.4.6. Network security infrastructure is configured to fail securely under
                        denial-of-service conditions to prevent unintended access or
                        uncontrolled traffic flow.
                 8.4.7. Detection, response, coordination, and escalation procedures for
                        denial-of-service events are defined within the Cyber Incident
                        Response Plan9 and supporting operational playbooks.

        8.5.     Secure Name/Address Resolution (Authoritative Source) (SC-20)
                 8.5.1. OIT Network Security utilizes an Internet Protocol Address Manager
                        (IPAM) administer authoritative Domain Name System (DNS) services
                        that support data origin authentication and integrity verification
                        artifacts.
                        8.5.1.1.   The authoritative DNS infrastructure is deployed in a
                                   distributed architecture to improve resilience and
                                   availability during DNS-based attack conditions.
                        8.5.1.2.   Administrative and synchronization communications
                                   between IPAM and authoritative DNS components are
                                   protected using secure network transport mechanisms.
                 8.5.2. Authoritative DNS services validate and respond to name/address
                        resolution requests using centrally managed directory and
                        configuration sources, as applicable.
                 8.5.3. The authoritative DNS service enables verification of a chain of trust
                        among parent and child zones, where child zones support secure
                        resolution services, when operating as part of a distributed,
                        hierarchical namespace.
                 8.5.4. Administrative access to authoritative DNS and IPAM services is
                        restricted, logged, and monitored. Detection and response to
                        anomalous or malicious name resolution activity is supported through
                        centralized logging, SIEM correlation, network monitoring, and SOC-
                        integrated incident response.
        8.6.     Secure Name/Address Resolution (Recursive or Caching Resolver) (SC-
                 21)
                 8.6.1. OIT Network Security utilizes DNS servers, which are Authoritative for
                        the Maine.Gov domain that securely provides DNS for zones delegated
                        by the DotGov registrar (see Definitions).
                 8.6.2. OIT Network Security utilizes secure recursive or caching DNS
                        resolvers to resolve external domain names for local clients. These
                        resolvers provide response integrity protections and validation
                        capabilities, or clients rely on authenticated channels to resolvers that
                        perform such validation on their behalf.
                 8.6.3. OIT Network Security utilizes access control lists, populated by other
                        DNS server names, which allow access only from a specified list of

        8.7.     Architecture and Provisioning for Name/Address Resolution Service
                 (SC-22)
                 8.7.1. OIT Network Security employs a distributed DNS architecture
                        administered through IPAM, with separation of internal and external

                        deployed in a primary and secondary configuration, with role-based
                        access controls restricting client access based on internal or external
                        service roles.
        8.8.     Session Authenticity (SC-23, (1), (5))
                 8.8.1. OIT Network Security implements session-level mechanisms to
                        protect the authenticity and integrity of communications and to
                        mitigate session hijacking, man-in-the-middle attacks, and the
                        insertion of false information into active sessions.
                 8.8.2. The OIT Computing Infrastructure and Services team, in collaboration
                        with the Unix, Oracle Database, and Middleware teams, implements
                        session authenticity mechanisms through the use of secure session
                        establishment mechanisms, including cryptographically protected
                        communication protocols and certificate-based trust relationships.
                 8.8.3. Invalidate Session Identifiers at Logout (SC-23(1))
                        8.8.3.1. OIT Network Security implements automatic session lockouts
                                 to systems and applications, once a user logs out of a
                                 workstation, through mechanisms such as a Failsafe Central
                                 Management System, which is a cyber guard for both internal
                                 and external session-level protection. In addition, OIT-
                                 configured applications and services invalidate or terminate
                                 associated session identifiers upon logout or session
                                 termination to prevent reuse of previously valid session
                                 identifiers.
                 8.8.4. Allowed Certificate Authorities (SC-23(5))

        8.10. Process Isolation (SC-39)
                 8.10.1. The OIT Computing Infrastructure and Services team, in
                         collaboration with the OIT Oracle Database team, maintains a
                         separate execution domain for each executing process.
                 8.10.2. Separation for Process Isolation: The OIT Computing Infrastructure
                         and Services team, in collaboration with the OIT Linux team, utilizes
                         Linux Kernel Features, Namespaces, Control Groups (Cgroups) (see
                         Definitions), and Capabilities to maintain separate execution domains
                         as well as Microsoft Distribution Points (DP) and Data Execution
                         Prevention (DEP). The Microsoft Data Execution Prevention (DEP)
                         policy is enabled by default in Windows 10 and Microsoft Server
                         2016 and later.
                        8.10.2.1. Microsoft DEP is used during process isolation as well as to
                                  perform additional checks on memory to prevent malicious
                                  code from running on the system.
                        8.10.2.2. Namespaces maintain a separate execution domain that is
                                  only visible to other Namespace processes.
                        8.10.2.3. Cgroups are provided through a pseudo-filesystem and
                                  implemented in the core Cgroups kernel code, while
                                  resource tracking, and limits are implemented in a set of
                                  per-resource-type subsystems such as memory and the
                                  central processing unit (CPU).

13.0. Definitions
        13.1. Advanced Encryption Standard (AES) 256: A U.S. Government-approved
              cryptographic algorithm that can be used to protect electronic data. The AES
              algorithm is a symmetric block cipher that can encrypt (encipher) and decrypt
              (decipher) information. Source NIST.21
        13.2. Chain of Trust: A certain level of trust in supply chain interactions so that each
              participant in the consumer-provider relationship provides adequate
              protection for its component products, systems, and services. Source NIST.22
        13.3. Content Delivery Network: A network of servers that is geographically
              dispersed to enable faster web performance by locating copies of web content
              closer to users or facilitating delivery of dynamic content (e.g., live video
              feeds).
        13.4. Control Group (Cgroups): A Linux kernel feature that limits, accounts for, and
              isolates the resource usage (CPU, memory, disk I/O, network, etc.) of a
              collection of processes.
        13.5. Data at Rest: The state of information when it is located on storage devices as
              specific components of information systems.
        13.6. Denial of Service (DoS) Attack: The prevention of authorized access to
              resources or the delaying of time-critical operations. (Time-critical may be
              milliseconds or it may be hours, depending upon the service provided). Source
              NIST.23
        13.7. Distributed Denial of Service (DDoS) Attack: A denial of service technique that
              uses numerous hosts to perform the attack. Source NIST.24
        13.8. DotGov Registrar: The domain name ‘.gov’ is a sponsored top-level domain
              (sTLD) in the Domain Name System of the internet. DotGov is derived from
              the word government, indicating its restricted use by government entities.
              The TLD is administered by the Cybersecurity and Infrastructure Security
              Agency (CISA), which is a component of the United States Department of
              Homeland Security.

        13.9. Endpoints: End-user devices such as desktops, laptops, and mobile devices.
              Endpoints serve as points of access to an enterprise network and create points
              of entry that can be exploited by malicious actors.
        13.10. Federal Information Processing Standard (FIPS): Publicly announced
               standards for use in computer systems by non-military American
               government agencies and government contractors.
        13.11. Information Asset: A discrete, identifiable piece of information technology,
               including hardware, software, firmware, systems, services, and related
               technology assets used to execute work on behalf of OIT or another State
               Agency.
        13.12. Non-Privileged User: A user who is unauthorized to perform security-
               relevant functions within various user accounts and processes.
        13.13. Manipulator-in-the-Middle Attack: An attacker positioned between two
               communicating parties in order to intercept and/or alter data traveling
               between them. For example, in the context of authentication, the attacker
               would be positioned between a claimant and a verifier during authenticator
               binding.
        13.14. Privileged User: A user who is granted rights that go beyond those of a typical
               business user to manage and maintain IT systems. Usually, these rights
               include administrative access to networks and devices and are separate from
               users’ administrative access to their own workstations.
        13.15. Recursive Query: A DNS query in which a resolver contacts a name server to
               perform a name lookup. The name server then returns a result or an error.
               The name server cannot refer the client to a different name server, but it can
               forward the query directly to another name server if it has a forwarder
               configured.
        13.16. Role-Based Access Control (RBAC): Access control based on user roles (i.e., a
               collection of access authorizations a user receives based on an explicit or
               implicit assumption of a given role). Role permissions may be inherited
               through a role hierarchy and typically reflect the permissions needed to
               perform defined functions within an organization. A given role may apply to a
               single individual or to several individuals. Source NIST. 25
