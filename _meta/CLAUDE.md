# _meta: the domain pack and the seed list

`domain.yml` defines the domain. `sources/<state>.yml` is the seed list, one file per state:
every instrument that state holds or is known to have. `corpus.yml` is toolkit configuration.

## Seed list (`sources/<state>.yml`)

- **One file per state; the file name is the `jurisdiction`.** A new state is a new file:
  `domain.yml`, `corpus.yml` and the other states' files do not change. The toolkit reads the
  directory as one group per file (`source_manifest_path: _meta/sources`), so drift runs and
  `--group <state>` work per state, and a baseline goes into the file that declares the id.
- **A file has `sources:` (the entries) and `left_out:`** (a list of `text:` items: what was
  seen on an official page and not seeded, with the reason). The seed check covers both
  (`src/check_seed_list.py`): the left-out record is required, a url may not be both seeded
  and left out, and a left-out line may not begin `id:` or `sha256:` (the toolkit edits those
  lines by regex). Key reference: `sources/README.md`.

- **An entry exists before its document does.** Propose entries in a PR; the owner's
  merge is the approval to fetch.
- **Find every instrument, then list it.** For each state: the CIO enabling statute, the
  cybersecurity statute, rules, executive orders in force, and every item in the CIO
  policy library. An instrument found and left out goes in `left_out:` with the reason.
- **Each entry carries:** `id`, `url` (the official source), `format` (declared, never
  inferred), `citation`, `title`, `doc_type`, `jurisdiction`, `tags`, `why_relevant`.
- **`jurisdiction`, `doc_type` and `tags` take only the values in `domain.yml`.** Apply
  the inclusion test there before adding an entry.
- **Citations and URLs are copied from the source page you fetched.** A candidate from a
  bulk dataset or a tracker is a lead to confirm at the official site.
- **Stub** an instrument that is not public or whose official source refuses the fetch:
  add `stub: true` and `stub_reason`. Official source only; no unofficial copies.
  A stub is a seed entry with no document file.
- **Index pages** (a policy library, an executive order list) are entries too, marked
  `watch_only: true`, so the monthly drift run reports additions and removals.
- **In force only.** When an instrument is replaced, the same PR removes the old entry
  and its document and adds the new one.

## Other files

- `domain.yml` changes only on an owner decision, recorded in `docs/spec.md` first. It does not
  list the states: they are the files in `sources/`.
- `graph.json` is generated by `src/build_graph.py`; `../STATUS.md`, `../llms.txt` (from
  `templates/llms.txt`) and `../CHANGELOG.md` (from `../changelog.d/`) are generated too.
  `scripts/regen.sh` rebuilds all of them. Regenerate; never edit.
- `eval/` is the analyst-question check (`questions.yml`, `expected/<state>.yml`, `baseline.json`; run by
  `src/eval_questions.py`). An expected file lists, per question, documents of that state with a verbatim
  quote each, or a `none_reason`. `baseline.json` is written by `python3 src/eval_questions.py --write-baseline`,
  never by hand and not by `regen.sh` (a regenerated baseline would accept a regression); commit it with
  any change to the questions or expected ids. Do not seed or edit documents to make a cell pass.
- `snapshots/` holds what the source served, written by the ingester. Never edit.
