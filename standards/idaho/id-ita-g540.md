I. DEFINITIONS

   See ITA Enterprise Guideline G105 (Glossary of Terms) for any definitions.

II. RATIONALE

   With the increasing use of mobile devices in the workplace, organizations must
   address security risks while maximizing productivity. Personal Digital Assistants
   (PDAs), tablets, and other handheld devices have become essential tools for the
   mobile workforce, enabling seamless communication and data access. However,
   these devices also introduce security challenges due to their ability to store and
   transmit information across wired and wireless networks.
   This guideline provides a framework for managing mobile devices, helping
   organizations establish policies to ensure secure and efficient use.

III. GUIDELINE

   A. Security Overview
      Basic mobile device security policies:
         1. Mobile devices connected to agency equipment should be password
            protected;
         2. The wireless port on mobile devices should be disabled when not in use;
         3. All mobile devices should have installed anti-virus software;
         4. Mobile devices that do not have up-to-date anti-virus software should be
            scanned for viruses prior to connecting to the agency network;
         5. Storing sensitive agency information is not recommended unless it is
            encrypted; and
         6. Mobile devices should have the latest security patches installed on their
            operating system.

   B. Physical Security

       Users must maintain the physical security of their mobile devices:
          1. Storage: Keep devices out of sight and covered when stored in a vehicle.
          2. Public Areas: Exercise caution in crowds, meetings, and security screening areas
             to prevent loss or theft.
          3. Identification: Attach a tag or label with contact information to facilitate recovery if
             lost.
          4. Reporting: Immediately notify the appropriate security or network administrator if
             a device is lost, stolen, or compromised.

   C. Device Security

       To safeguard State systems and data, follow these security practices for mobile
       devices:
          1. Software Security: Script files must not store user IDs or passwords for State
             systems.
          2. Authentication: Enable power-on authentication on all devices.
          3. Unattended Devices: Use a screen saver with password protection or a keyboard
             lock.
          4. Password Guidelines: Refer to Information Technology Enterprise Standard
             S6030 – Identity and Authentication.
          5. Travel Precautions: Transport mobile devices as carry-on luggage unless
             regulations require otherwise.
          6. Updates & Patches:
                 a) Keep devices updated with the latest security patches and virus
                     protection.
                 b) Automate updates when possible, and apply critical patches within 48
                     hours of release.
          7. Firewall Protection: Install and update firewall software on devices connecting to
             the State network from outside the State firewall.
          8. Data Security:
                 a) Enable remote wipe capability to protect State data on lost or stolen
                     devices.
                 b) Use a Mobile Device Management solution for automated security
                     enforcement.

   D. Data Security

       To safeguard State data

          1. Encryption: Encrypt sensitive or confidential data stored on mobile devices. For
             added security, encrypt data, store it on removable media, and keep the media
             separate from the device or case.
          2. Device Disposal: Include mobile devices in the surplus equipment and disposal
             lifecycle to ensure complete data removal before returning them to vendors or
             surplus. Refer to ITA Guideline G550 – Cleansing Data from Surplus Computer
             Equipment for proper disposal procedures.

   E. Communication and User Education

       A successful mobile device policy requires ongoing communication and user
       education to ensure security and efficiency. Regular updates on policy changes,
       IT support, and provisioning should be shared with users through training
       sessions that encourage discussion and knowledge sharing.

       User Education Essentials

       Effective security training reduces risks and helps users protect both agency and
       personal data. At a minimum, user education programs and policies should:
          1. Encourage Accountability: Users should understand the importance of following
             security policies and taking common-sense precautions.
          2. Highlight Risks & Consequences: Explain the potential impact of device loss,
             including risks to agency reputation and exposure of sensitive personal data.
          3. Provide Easy-to-Use Security Tools: Ensure authentication mechanisms,
             encryption, and security controls are accessible and simple to implement.
          4. Demonstrate Real-World Threats: Use training sessions to show how mobile
             devices are vulnerable to theft and loss and outline preventive measures.

       Workshops and short online training sessions focusing on security threats and
       best practices can help users better safeguard their devices and data.

   F. Agency Policies

       Agencies should develop mobile device policies that align with their specific
       security and operational needs. Consider incorporating the following elements:
          1. Application Restrictions: Define which apps users are permitted to download and
             install.
          2. Data Access & Restrictions: Establish guidelines for authorized and restricted
             data, including sensitive information.
          3. Connectivity Controls: Specify approved connectivity methods, such as Wi-Fi,
             Bluetooth, or external communication ports.

       A more restrictive policy tailored to agency requirements can enhance security
       while maintaining efficiency.

   G. Tiered Mobile Device Management Model

       Some agencies may require a more dynamic mobile device management approach
       focused on data rather than device type. Agencies that meet the following requirements
       may implement a tiered security model, which will be considered compliant with ITA
       policy and standards:
           1. Data Classification: The agency must classify all data per ITA Enterprise Policy
               P4130 (Information Systems Classification) and ITA Enterprise Guideline G505
               (Data Classification and Labeling Guideline).
           2. Technical Controls: Effective measures must be in place to manage and enforce
               classified data flow across networks and endpoints (e.g., data loss prevention
               (DLP), encryption, mobile device management (MDM), etc.).
           3. Stricter Security Requirements: The tiered model must enforce security controls
               that exceed those outlined in the standard policy.
           4. Data-Centric Approach: Security classification of devices must be based on the
               highest classification of data the user regularly interacts with.
           5. Resource Considerations: Agencies must assess the staffing and resource
               requirements necessary to manage a tiered model compared to a “flat” model.

       Requirements by Classification:

       Agencies must implement security controls based on the classification of mobile device
       usage.

          Classification 1: Public

          Devices in the category:
             1. Are personally owned and never used for state business.
             2. Only interact with openly available websites, documents, and information.
             3. May connect only to unauthenticated, public state-operated networks.
             4. No mobile device management (MDM) client is required, and no policies are
                enforced.

          Classification 2: Limited

       Devices in this category interact with limited-classified data, such as internal email,
       which may or may not be exempt from public record requests. These devices may be
       personally-owned or state-owned and must have a Mobile Device Management (MDM)
       client to monitor and enforce security policies.

       Required Security Controls:
              1. Device password required
              2. Screen lock and inactivity timeout (10 minutes limit)
              3. Device wipe and reset after 10 consecutive incorrect password attempts
              4. Anti-virus software
              5. Web content filtering
              6. Encryption of data at-rest (including SD card if present)

              7. Encryption of data in-transit (where possible)

          Classification 3: Restricted

       Devices in this category must be state-owned and interact with restricted-classified
       data, such as:
              1. Technical network or security information
              2. Administrator passwords
              3. Personally identifiable information (PII)

       This type of information is exempt from public records requests, requiring stricter
       security measures. In addition to Classification 2 controls, the following must be
       implemented:
               1. Application Whitelisting: Only approved applications may be installed.
               2. Data Loss Prevention (DLP): Enforce policies to prevent unauthorized data
                  exposure.
               3. External Media Restrictions: Limit SD card use to essential operational
                  functions.
               4. Removable Storage Restrictions: Prohibit devices from functioning as
                  removable storage.
               5. Backup & Synchronization Controls: Restrict usage of sync applications (e.g.,
                  Dropbox, iCloud, OneDrive).
               6. Wireless Hotspot & Tethering Restrictions: Enabled only on a per-device
                  basis with supervisor approval and a documented business case.

       These controls ensure enhanced security for sensitive data while maintaining
       compliance with agency policies.

          Classification 4: Critical

       Devices in this category must be state-owned and interact with critical-classified
       data, where disclosure could result in significant penalties, serious injury, disability,
       or loss of life. This information is exempt from public record requests and requires
       the highest security standards.

       Additional Security Requirements (Beyond Lower Classifications):
          1. Persistent VPN Connections: Required on all cellular and non-State networks.
          2. Restricted Wireless Access: Allow only necessary network connections.
          3. Personal Area Network (PAN) Restrictions: Limit Bluetooth and NFC to essential
              operations and only for the required duration.
          4. Hardware Access Restrictions: Limit camera, microphone, and other hardware
              use to operational needs.
          5. Controlled Wireless Hotspot & Tethering: Enabled only on a per-device basis
              with supervisor approval, and usage must be purpose-driven and time-limited.

       Requirements for Classifications 2-4 (Limited through Critical):
          1. Secure Device Wiping & Resetting: Required before reissuance.
          2. Pre-Issuance Security Measures: Devices must be secured before deployment.
          3. Mobile Device Management (MDM) Client Required: Enforce policy compliance.
          4. Boot-Level Password Protection: Devices must require passwords before fully
              booting (swipe, pattern, and PIN are insufficient).
          5. Screen Lock & Inactivity Timeout: Must align with P4550 Mobile Device
              Management Policy.
          6. Prohibited Sideloading: Installing unauthorized applications must be disabled.
          7. Mandatory Security Protections: Anti-virus software, web content filtering, and
              encryption (at-rest & in-transit) are required.

       Reference Appendix A for a graphical representation of these classifications and
       required controls.
